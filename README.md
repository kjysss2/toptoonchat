# 탑툰챗 카운터

[대시보드](https://kjysss2.github.io/toptoonchat/)에서 공개 작품별 View·Chat 누적 카운터와 이전 수집 대비 증감을 봅니다. 공개 카운터는 매출이나 실제 이용자 수와 같지 않습니다.

## 자동 업데이트

- 기본 예약: 매일 **한국시간 오전 07:00** (`0 22 * * *`, UTC 기준).
- 보완 예약: **07:17, 07:37, 08:07, 09:07 KST**. 앞선 실행이 지연되거나 실패하면 다시 시도합니다.
- 해당 한국 날짜의 07:00 이후 정상 수집이 있으면 **재수집하지 않습니다**. 늦게 도착한 예약이 아침 데이터를 덮어쓰지 않습니다. 자정이나 새벽에 수동 수집한 기록은 아침 수집을 막지 않습니다.
- 정상 수집 후에는 `dist/data/snapshots.json`을 커밋하고 GitHub Pages를 직접 배포합니다. 수집을 건너뛴 실행도 배포는 수행하므로, 이전 배포 실패를 복구할 수 있습니다.
- 두 배포 작업은 같은 `github-pages` 실행 그룹을 사용하며 시작 시 최신 `main`을 읽습니다.
- 사이트가 열려 있으면 1분마다 저장된 데이터를 다시 읽고, 다른 탭에서 돌아와도 갱신합니다. 네트워크 오류 때는 기존 데이터를 유지하고 재시도합니다.
- PC나 Codex를 켜 둘 필요가 없습니다.

**GitHub Actions는 정시 실행을 보장하지 않습니다.** 정각 부하로 예약 작업이 지연되거나 누락될 수 있으며 보완 예약도 같은 제한을 받습니다. 07:00은 실행 목표이고 실제 반영은 수집·배포가 끝난 뒤입니다. 정확한 실행이 필수라면 별도 서버/외부 스케줄러가 필요합니다. [GitHub 공식 설명](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

## 2026-09-10 점검에서 확인한 원인

기존 시간 설정은 이미 07:00 KST로 맞았습니다. [2026-09-09 예약 실행](https://github.com/kjysss2/toptoonchat/actions/runs/34292079700)은 08:45 KST에 시작되어 08:47에 수집·배포를 완료했습니다. 예약 시작이 약 106분 지연됐습니다. 기존 화면은 최초 접속 시에만 데이터를 읽어 열린 탭에는 새 수집 결과가 자동 표시되지 않았습니다.

보완 예약, 아침 수집 중복 방지, HTTP 일시 오류 재시도, 배포 동시 실행 조정, 브라우저 자동 갱신을 추가했습니다. 화면은 실제 수집 시각을 표시하며 오늘 7시 이후에도 오래된 데이터이면 수집 대기·지연 상태를 표시합니다.

## 지금 바로 실행하기

1. [수집 Actions 화면](https://github.com/kjysss2/toptoonchat/actions/workflows/scrape.yml)을 엽니다.
2. 오른쪽 **Run workflow / 워크플로 실행**을 누릅니다.
3. 브랜치는 **main**으로 둡니다.
4. 오늘 아침에 이미 수집한 데이터까지 다시 가져오려면 **Force a fresh capture…**를 체크합니다. 체크하지 않으면 중복 수집은 건너뛰고 배포만 복구합니다.
5. 초록색 **Run workflow**를 누릅니다.
6. 생성된 실행을 열고 **capture** 작업의 모든 단계가 초록색인지 확인합니다.
7. [사이트](https://kjysss2.github.io/toptoonchat/)의 **최종 수집** 시간이 바뀌었는지 확인합니다. 기존 버전 화면을 오래 켜 두었다면 이번 수정 후 한 번 새로고침합니다.

## 계속 오래된 데이터가 보일 때

- **오늘 실행 자체가 없음:** 예약 지연 여부를 확인하고 위 절차로 수동 실행합니다. Actions에 비활성화 안내가 있으면 **Enable workflow**로 다시 활성화합니다. 공개 저장소는 60일 동안 저장소 활동이 없으면 예약이 비활성화될 수 있습니다.
- **Capture 단계 실패:** 실행 로그의 원본 사이트 연결/파싱 오류를 확인합니다. 실패한 수집은 기존 파일을 덮어쓰지 않습니다.
- **Save 단계 실패:** `contents: write` 권한 또는 브랜치 보호 규칙을 확인합니다.
- **Deploy 단계 실패:** 저장소 **Settings → Pages → Build and deployment → Source**가 **GitHub Actions**인지 확인합니다. `github-pages` 환경에 수동 승인 조건이 있다면 자동 실행도 승인 대기할 수 있습니다.
- **성공했는데 시간이 그대로:** 이미 오늘 아침 수집이 있어 건너뛴 것인지 Capture 로그를 확인합니다. 새 데이터가 필요하면 force를 체크하여 실행합니다.

## 데이터 해석

공개 홈·탐색·랭킹에서 작품 링크를 찾아 각 상세 페이지의 공개 카운터를 읽습니다. 일별 스냅샷은 한국 날짜 기준으로 저장하며 강제 수집하면 같은 날짜 값이 교체됩니다. 순증은 실제 이전 수집과 비교하므로, 지연이나 수집 누락이 있으면 정확히 24시간 차이가 아닙니다. 관측 작품 목록 변화도 합계에 영향을 줄 수 있습니다.

기존 초기 기록에는 순위만 있고 View·Chat이 없을 수 있습니다. 카운터가 있는 서로 다른 날짜의 기록이 두 개 쌓여야 증감이 나옵니다. 실제로 수집하지 못한 과거 07:00 수치는 소급 생성하지 않습니다.
